# GraalVM 25+ reachability-metadata.json 格式备忘

> 本文是 GraalVM native-image **统一可达性元数据格式**（`reachability-metadata.json`）
> 的字段级参考备忘，供 beangle 构建插件（AotPlugin / ProxyPlugin）与生成器后续维护时查阅。
> 适用范围与前提：**GraalVM for JDK 25 及之后**，对应 JSON schema
> `reachability-metadata-schema-v1.2.0.json`（25 文档当前指向的版本）。
> 若面向更早版本（21/22/24 系），schema 不同，见文末[版本演进](#10-版本演进速查)。

---

## 1. 定位与背景

native-image 是"封闭世界"分析，运行期动态访问（反射、JNI、资源、序列化、动态代理、
lambda、FFM）需要构建期元数据。GraalVM 把原先按功能拆分的多个 JSON（`reflect-config.json`、
`proxy-config.json`、`resource-config.json`、`serialization-config.json`、`jni-config.json`、
`bundles`……）统一为**一个顶层对象、按功能分数组**的 `reachability-metadata.json`：

- 每个功能数组的条目仍保留旧格式的成员语义（方法/字段/构造器注册），只是字段名统一；
- 序列化、JNI、代理等语义**折叠进 reflection/resources 条目**，不再是顶层独立数组
  （v1.2.0 起，见第 10 节）；
- 顶层不允许自定义键（v1.2.0 `additionalProperties: false`），出错早、易校验。

### 1.1 最低版本要求（备忘重点）

- 本文按 **GraalVM 25+（JDK 25 主线，schema v1.2.0）** 整理；25 之前的版本请用对应的
  旧 schema 校验（assets 目录下按版本存放）。
- GraalVM 21/22/24 系也能读取新格式的早期版本（v1.x），部分新字段可能不识别；
  不要假设旧版本具备 v1.2.0 全部语义。
- native-image 对**旧的 reflect-config.json 等分文件格式仍然向后兼容读取**（25 上旧文件
  仍能生效），但官方明确在向新格式迁移，新输出一律写 `reachability-metadata.json`。
- 未来版本中"反射缺失即报错"的严格行为将成为默认，建议尽早采用新格式（见第 9 节）。

## 2. 文件位置与自动发现

- **文件名固定**：`reachability-metadata.json`（必须是这个名字，native-image 按名发现）。
- **约定目录**：classpath 条目下 `META-INF/native-image/<groupId>/<artifactId>/`，
  `<groupId>/<artifactId>` 只是推荐的两级布局约定，native-image 扫描 classpath 各条目
  `META-INF/native-image/` 下的该文件名并**自动合并所有片段**，无需任何构建参数。
- 多个片段同名不冲突：beangle 的 AotPlugin 写 `META-INF/native-image/beangle/`、
  ProxyPlugin/生成器写 `META-INF/native-image/beangle/data/`，native-image 构建时全部读入
  合并（本仓库已在 GraalVM CE 25.3.4.1 实测）。
- 依赖库同样适用：hibernate-core fork jar 内嵌的
  `META-INF/native-image/org.hibernate.orm/hibernate-core/` 片段会被自动应用。
- **不要在同一布局里混留新旧格式**：旧 `reflect-config.json` 与新的 reflection 条目语义
  相同、会被重复注册（且 strict 模式会对旧语义报差异）。beangle 插件/生成器在写新文件前
  会删除同名布局下的旧文件（`LegacyConfigFiles`）。

## 3. 顶层结构与 schema 校验

顶层是**单个对象**，v1.2.0 合法键只有四个：

| 顶层键 | 类型 | 说明 |
|--------|------|------|
| `comment` | string 或 string 数组 | 整个文件的注释（生成时间、来源、作者等），纯信息、无运行时语义 |
| `reflection` | 数组 | 反射注册（含代理、lambda、序列化、JNI 折叠条目） |
| `resources` | 数组 | 资源（glob）与资源包（bundle）注册 |
| `foreign` | 对象 | FFM API（downcalls / upcalls）注册 |

```json
{
  "comment": ["Generated by org.beangle.commons.aot", "see docs/graalvm-reachability-metadata.md"],
  "reflection": [],
  "resources": []
}
```

校验（随手可跑）：

```bash
# 用官方 schema 校验
python -m jsonschema -i reachability-metadata.json \
  https://github.com/oracle/graal/raw/master/docs/reference-manual/native-image/assets/reachability-metadata-schema-v1.2.0.json
```

> 注意：官方文档页"Metadata JSON Format Reference"的表格仍写着 reflection/jni/resources
> "three main sections"，那是沿袭旧文档的通用描述，与 v1.2.0 schema 不符（v1.2.0 顶层没有
> `jni` 数组）。**一切以 schema 文件为准。**

## 4. `reflection` 条目（核心）

条目是对象，**必填 `type`**（其余全部可选，缺省为 false/空）。

### 4.1 type 的三种形态

`type` 可以是类名字符串，也可以是对象（代理或 lambda）：

```json
{ "type": "com.example.MyClass", ... }                        // 普通类/接口/枚举
{ "type": { "proxy": ["java.lang.Runnable", "java.io.Serializable"] }, ... }  // JDK 动态代理
{ "type": { "lambda": { "declaringClass": "com.example.Host", "interfaces": ["java.util.function.Function"] } }, ... } // lambda 类
```

- `type.proxy`：实现代理类所需**接口全限定名的有序列表**（顺序即运行时 `Proxy` 语义，
  相同集合不同顺序是不同代理类）；注册后该代理类可被 `Proxy.newProxyInstance` 反射创建。
- `type.lambda`：必填 `declaringClass`（lambda 所在类）与 `interfaces`（非空，lambda 实现的
  函数式接口）；`declaringMethod` 可选（对象，形如 `{"name": "...", "parameterTypes": [...]}`，
  用于精确定位同一个 declaringClass 里的多个 lambda）。

### 4.2 注册字段

| 字段 | 类型/默认 | 语义 |
|------|-----------|------|
| `type` | 见上 | **必填** |
| `allPublicMethods` | bool, false | 全部 public 方法（含继承）可反射调用 |
| `allDeclaredMethods` | bool, false | 全部 declared（本类声明）方法可反射调用 |
| `allPublicConstructors` | bool, false | 全部 public 构造器 |
| `allDeclaredConstructors` | bool, false | 全部 declared 构造器 |
| `allPublicFields` | bool, false | 全部 public 字段（含继承）可读写 |
| `allDeclaredFields` | bool, false | 全部 declared 字段可读写 |
| `methods` | 数组 | 定点方法注册（见 4.3） |
| `fields` | 数组 | 定点字段注册，元素 `{ "name": "..." }`（仅 name） |
| `unsafeAllocated` | bool, false | 允许 `Unsafe.allocateInstance` / JNI `AllocObject` 无构造器实例化 |
| `serializable` | bool, false | 注册为标准 Java 序列化类型（对应旧 serialization-config） |
| `jniAccessible` | bool, false | 类型及其已注册字段/方法同时开放给 JNI（对应旧 jni-config） |
| `condition` | 对象 | 条件注册，见第 5 节 |
| `reason` | string 或数组 | 说明性文字，无运行时语义 |

- v1.2.0 条目 `additionalProperties: false`，**`comment` 只允许出现在顶层**，条目内
  写 `comment` 会校验失败；需要注释就写 `reason`，文件级注释用顶层 `comment`。

### 4.3 methods 定点注册

```json
{ "name": "<init>", "parameterTypes": [] }
{ "name": "writeReplace", "parameterTypes": [] }
{ "name": "setName", "parameterTypes": ["java.lang.String"] }
{ "name": "parseInt", "parameterTypes": ["java.lang.String", "int"] }
```

- `name` 与 `parameterTypes` **都必填**（parameterTypes 可空数组）；
- 构造器用名字 `<init>`；参数类型用全限定名（基本类型直接 `int`/`boolean` 等）；
- 数组/多维参数等少见写法的精确形态，直接抄 native-image-agent 的输出最稳妥。

### 4.4 完整示例（含折叠语义）

```json
{
  "reflection": [
    { "type": "com.example.MyClass",
      "allPublicMethods": true,
      "allPublicConstructors": true },
    { "type": "com.example.Detail",
      "methods": [{ "name": "<init>", "parameterTypes": [] },
                  { "name": "setName", "parameterTypes": ["java.lang.String"] }],
      "fields": [{ "name": "id" }],
      "reason": "read via BeanInfo at startup" },
    { "type": { "proxy": ["org.hibernate.proxy.HibernateProxy", "com.example.Entity"] },
      "condition": { "typeReached": "com.example.Service" } },
    { "type": "com.example.State",
      "serializable": true },
    { "type": "com.example.NativeBridge",
      "allPublicMethods": true, "jniAccessible": true }
  ]
}
```

### 4.5 JDK URL 协议 handler（http/https/…）

GraalVM 25 起 `--enable-url-protocols` / `--enable-http(s)` 弃用，JDK URL 协议改为
**reachability metadata 驱动**：运行期 `URL` 机制按
`sun.net.www.protocol.<protocol>.Handler` 的名字反射
`Class.forName(...).getDeclaredConstructor().newInstance()` 实例化 handler，因此要把
**handler 类与其无参构造器**登记进 `reflection` 条目，否则运行期抛
`MalformedURLException: Accessing a URL protocol that was not enabled ...`。

官方推荐条目（http/https 必须两条都写；ftp/jar/jmod/mailto 等替换协议名即可）：

```json
{
  "reflection": [
    { "type": "sun.net.www.protocol.http.Handler",
      "methods": [ { "name": "<init>", "parameterTypes": [] } ] },
    { "type": "sun.net.www.protocol.https.Handler",
      "methods": [ { "name": "<init>", "parameterTypes": [] } ] }
  ]
}
```

要点：

- 类在 `java.base` 内部包，编译期不能 `classOf` 引用（包未导出），只能**按类名登记**；
- 这些类型是显式点名的 JDK 类型，登记必须绕过普通"JDK 前缀类跳过"过滤（commons 的
  `AotHints.registerConstructor` 即为此设计：按名记录，输出上述精确 `methods` 条目）；
- `allDeclaredConstructors: true` 等粗粒度标志**同样有效**（实测 GraalVM CE 25.3.4.1
  http/https 均可连）；精确 `methods` 形态是官方示例，体积最小、语义最明确，优先采用；
- `file`/`resource`/`jrt` 协议由 native-image 内置，无需登记。

参考：<https://www.graalvm.org/latest/reference-manual/native-image/dynamic-features/URLProtocols/>

## 5. 条件注册 `condition`

条目级可选字段，用于**按运行时可达性收窄注册面**、控制镜像体积：

```json
{
  "type": "com.example.Detail",
  "allPublicConstructors": true,
  "condition": { "typeReached": "com.example.Service" }
}
```

语义（官方原文要点）：

- 只有当 `typeReached` 指定的类型在**运行时被"到达"**后，本条目才可用；到达时刻 =
  该类型（或它的某个子类型）**类初始化即将开始之前**起，含已初始化状态；
- 被标记为 `initialize-at-build-time`（或子类型在 classpath 且被如此标记）的类型同样视为
  已到达；
- **数组类型永远不会被标记为到达，不能用作条件**；
- 条件条目在 **build time 若条件类型可达则合入镜像**（影响体积），但运行期真正"可用"
  仍以条件到达为准；条件未达时访问该元素会抛缺注册错误。
- `condition` 只有 `typeReached` 一个字段（v1.2.0 schema `additionalProperties: false`）。
  旧格式的 `typeReachable`（可达性分析语义）对应新格式的 `typeReached`（运行期到达语义），
  二者不等价，迁移时注意。

## 6. `resources` 条目

`resources` 数组每个元素是对象，**`glob` 与 `bundle` 二选一**；两者都可有可选字段
`module`、`condition`、`reason`：

```json
{
  "resources": [
    { "glob": "META-INF/services/org.example.Spi", "reason": "ServiceLoader" },
    { "glob": "**/*.ftl" },
    { "bundle": "com.example.messages", "condition": { "typeReached": "com.example.I18n" } }
  ]
}
```

### 6.1 glob：是 glob 不是正则

- `glob` 匹配资源名：`*` 匹配单层、`**` 跨层、无通配符即精确文件名；
- **与正则不同**：`.*\\.xml`、`META-INF/services/.*` 这类正则写法在 `glob` 下匹配不到
  `beangle.xml`/服务文件；有效写法是精确名（`beangle.xml`）、`*.xml`（单层）或
  `**/*.xml`（跨层）。旧 `-H:IncludeResources` 与 `resource-config.json` 是**正则**语义，
  两者不要混用。
- 资源名不含前导 `/`，按 classpath 条目根起算（如 `com/example/a.properties`、
  `META-INF/...`）。

### 6.2 module：缺省即全 classpath（非 per-jar）

- **不带 `module` 的 `glob`/`bundle` 在整个 classpath 上匹配**：一处声明即可覆盖全部依赖
  jar 中的同名/同模式资源；`module` 字段才是把作用域限定到某个 Java module 的选项。
- 这正是"集中式"方案成立的前提：beangle 各库的 registrar 在终端聚合时显式声明资源
  glob（如 commons 的 `META-INF/services/*`、`beangle.xml`、`**/*.zh_CN`，template 的
  `**/*.ftl`），一处声明即可覆盖所有依赖库资源。结论已在 GraalVM CE 25.3.4.1 实测：
  元数据片段内嵌于 jar A、实际资源位于 jar B，glob 仍全局命中；运行期亦可用
  `ClassLoader.getResources("beangle.xml")` 验证资源来自各 jar。
- 目标版本是纯 classpath（非 JPMS module）应用时，一律省略 `module`。

### 6.3 bundle

- `bundle` 是 `ResourceBundle` 的 base name（如 `com.example.messages`），不再用旧的独立
  bundles 数组。

## 7. `foreign`（FFM，简介）

`foreign` 是对象，含 `downcalls` / `upcalls` / `directUpcalls` 三个数组，注册
`java.lang.foreign.Linker` 调用的函数描述符：

```json
{
  "foreign": {
    "downcalls": [{ "returnType": "int", "parameterTypes": ["java.lang.String"] }],
    "upcalls": [{ "returnType": "void", "parameterTypes": ["int"] }],
    "directUpcalls": [{ "class": "com.example.Callback", "method": "invoke",
                       "returnType": "void", "parameterTypes": ["int"] }]
  }
}
```

- `downcalls` / `upcalls`：每个描述符必填 `returnType` + `parameterTypes`（值为
  **memory layout 描述**，允许 canonical layout，不是类名），可选 `condition` /
  `reason`。`downcalls` 的 `options` 支持 `captureCallState`(bool) /
  `critical`(`{ "allowHeapAccess": bool }`) / `firstVariadicArg`(int)；
  `upcalls` 的 `options` 目前为空对象（schema 注明 upcall 尚不允许 linker options）。
- `directUpcalls`：注册**具体 Java 方法**的 direct upcall，必填 `class`（全限定名，
  含 `$` 内部类）+ `method`（方法名），再加 `returnType` / `parameterTypes`
  memory layout；`options` 目前同样为空。
- 详细语义与示例见官方 FFM-API.md（文末链接）。

## 8. 与旧分文件格式的对照

| 旧格式（仍被兼容读取） | 新格式对应（v1.2.0） | 差异要点 |
|------------------------|----------------------|----------|
| `reflect-config.json` | `reflection` 数组 | 顶层是**数组** vs 顶层对象；条目 `name` → `type` |
| `proxy-config.json` | `reflection` 条目 `type: { "proxy": [...] }` | 不再单独成文件 |
| `serialization-config.json` | `reflection` 条目 `"serializable": true` | 顶层 `serialization` 数组 v1.2.0 已移除 |
| `jni-config.json` | `reflection` 条目 `"jniAccessible": true` | v1.2.0 顶层无 `jni` 数组（官方文档表格是旧文，以 schema 为准） |
| `resource-config.json`（正则资源） | `resources` 条目 `glob` | 正则 → glob 语义，见 6.1 |
| bundles（`ResourceBundle`） | `resources` 条目 `bundle` | 不再单独成段 |
| `typeReachable`（旧条件） | `typeReached` | 语义从可达性改为运行期到达，见第 5 节 |

迁移建议：新写一律用新格式；生成/清理时把同布局下的旧文件一并删除，避免 native-image
同时读两种格式导致重复注册。

## 9. 严格模式与排错（25 系新增/演进）

- `--exact-reachability-metadata`：构建时开启"精确可达性元数据"模式，缺失注册即报错；
  可只对指定包启用：`--exact-reachability-metadata=<逗号分隔的包前缀>`。
- 运行期探错（不必整体切 exact）：
  - `-XX:MissingRegistrationReportingMode=Warn`：把缺失注册当告警输出（摸底用）；
  - `-XX:MissingRegistrationReportingMode=Exit`：遇到缺失注册立即打印并退出
    （测试期验证元数据完备性用；注意别被 `catch (Throwable)` 吞掉而静默）。
- 官方说明"反射的 user-friendly 严格实现未来会成为默认"，现在写新格式、尽早清理旧语义
  可避免后续版本翻车。

## 10. 版本演进速查

| schema | 顶层键 | 说明 |
|--------|--------|------|
| v1.0.x | （早期合并格式） | 框架期，各功能独立数组 |
| v1.1.0 | `comment` `reflection` `jni` `serialization` `resources` `bundles` `foreign` | 旧布局：JNI/序列化/资源包仍是顶层数组 |
| **v1.2.0（25+ 本文档目标）** | `comment` `reflection` `resources` `foreign` | JNI → `jniAccessible`、序列化 → `serializable`、资源包 → `bundle`，全部折叠进条目 |

- v1.2.0 相对 v1.1.0 的移除项：顶层 `jni` / `serialization` / `bundles` 三个数组；
  reflection 条目新增 `serializable` / `jniAccessible` / `unsafeAllocated`。
- GraalVM JDK 21 分支通过 backport 也支持新格式与 v1.x schema（个别新特性可能不可用），
  若必须支持 21 系构建，请以对应版本 schema 校验，不要照抄 25 全部字段。
- schema 文件随 GraalVM 演进，均在 oracle/graal 仓库
  `docs/reference-manual/native-image/assets/` 下按版本号存放，可随时对照。

## 11. beangle 项目中的用法（关联本仓库）

- **AotPlugin（终端集中式）**：遍历整个运行时 classpath，按
  `aot-registrars.txt` / `meta-registrars.txt` / `beangle.xml` 收集 registrar 与 web
  initializer，由 `AotHintGenerator` 生成**一份合并配置**到
  `META-INF/native-image/beangle/reachability-metadata.json`（随终端产物打包），覆盖反射、
  资源 glob、代理、序列化；资源 glob 由各库 registrar 经 `registerPattern` 按 glob
  语义显式声明，插件不再扫描资源后缀；需要 run-time-init 时另写
  `native-image.properties`。
- **ProxyPlugin / BeangleProxyGenerator（终端集中式）**：为跨 classpath 合并出的
  Hibernate 实体预生成 `<Entity>$HibernateProxy.class`，并写
  `META-INF/native-image/beangle/data/reachability-metadata.json` 片段（reflection 条目：
  无参构造器 + `writeReplace` + `allPublicMethods`），与 AotPlugin 的聚合文件分处不同子目录，
  native-image 自动合并。
- 三段式产物示意：

```text
<终端 war/jar>/
└── META-INF/native-image/
    ├── beangle/reachability-metadata.json      # AotPlugin：全 classpath 合并
    └── beangle/data/reachability-metadata.json # ProxyPlugin：Hibernate 代理注册
```

```json
// beangle/data 片段（ProxyPlugin 产物）
{
  "reflection": [
    { "type": "org.beangle.ems.model.Employee$HibernateProxy", "allPublicMethods": true,
      "methods": [ { "name": "<init>", "parameterTypes": [] },
                   { "name": "writeReplace", "parameterTypes": [] } ] }
  ]
}
```

```json
// beangle/ 聚合片段（AotPlugin 产物，示意）
{
  "reflection": [
    { "type": "org.beangle.ems.app.BeangleRegistrar", "allPublicMethods": true, "allPublicConstructors": true }
  ],
  "resources": [
    { "glob": "META-INF/services/*" },
    { "glob": "beangle.xml" },
    { "glob": "**/*.zh_CN" }
  ]
}
```
